Reload sheet — drift preview before commit

When the user reloads a past session, the sheet is the same shape but adds a What's different now block. Reload applies the original session's additions/subtractions against the current default, never a frozen snapshot — so the user sees what will actually happen before committing.

Principle 10 + Bret Victor. Reload would surprise the user if it silently re-enacted state from days ago against a world that has changed. The drift preview removes the surprise. The user says yes to this reload, not to a memory.

Design notes

Five fields total. Name, duration, base, agents, tracking. Three require user input (name auto-suggested, default-access pre-selected, tracking on by default when writes are allowed). Form completes in ~15 seconds first time.
"Start blank" is the second radio row, not buried. Same visual weight as "Your default access." The user who wants to be conservative shouldn't have to dig. Thaler/Sunstein applied honestly.
Drift preview is yellow, not red. A drifted reload isn't a danger — it's a normal consequence of time passing. Yellow says "look at this" without "stop." Red would over-cry-wolf.
"Edit additions…" on the reload sheet. Power-user shortcut into the Access/Mail Session tab so the user can revise the additions before starting the resumed session. Not the primary action; a sibling.
Sheet is acceptable here. Raskin: a quasimode the user invoked is acceptable. The session-start sheet is small, modal-only-while-the-user-is-on-it, and dismissible with Esc. Not a daemon-imposed interrupt.
