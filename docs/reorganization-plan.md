# Manifold Repo Reorganization Plan

A pre-launch audit and proposed restructure for shipping Manifold as a public Apache-2.0 macOS app. Written 2026-05-01.

This document is the plan. It is not a description of changes already made.

## Goals

1. A first-time visitor on GitHub can read the README, run the Quick Start, and not hit a broken link, broken image, or confusion about which doc is canonical.
2. A first-time contributor can clone, build, and test on a clean machine with one command, and a CI run on their PR confirms it.
3. The repo presents an honest, narrow product surface — internal iteration drafts, scratch work, and trademark-encumbered third-party assets do not ship.
4. The hybrid SwiftPM + Xcode build keeps working with no path surprises.

## Principles

- **Sources/, Tests/, and ManifoldApp/ are sacred.** They map to `Package.swift` and `project.yml`. Don't reshape them in this pass.
- **One canonical doc per topic.** Architecture, product spec, design standards each live in exactly one place. Iteration drafts go to `docs/archive/` if kept at all.
- **Anything ignored should also be off-disk.** A folder you can see in Finder but git ignores is still confusion.
- **Reversibility before polish.** Use `git mv`, not delete-then-create, so history follows files. Run the verification commands from `CLAUDE.md` after each batch.

## Add CI

`.github/workflows/ci.yml`:

```yaml
name: CI
on: [push, pull_request]
jobs:
  swiftpm:
    runs-on: macos-latest  # pin to macos-26 once available on hosted runners
    steps:
      - uses: actions/checkout@v4
      - uses: maxim-lobanov/setup-xcode@v1
        with: { xcode-version: latest-stable }
      - run: swift build
      - run: swift test
  xcode:
    runs-on: macos-latest
    steps:
      - uses: actions/checkout@v4
      - uses: maxim-lobanov/setup-xcode@v1
        with: { xcode-version: latest-stable }
      - run: xcodebuild -project Manifold.xcodeproj -scheme Manifold -configuration Debug build CODE_SIGNING_ALLOWED=NO
```

The PR-template checklist becomes a CI-enforced status check, not a self-attestation.

**Caveat to research:** macOS 26 + Xcode 26 may not be on GitHub-hosted runners yet. If not, choose between (a) self-hosted runner, (b) relaxing min macOS for CI only, (c) shipping a degraded check (build-only, no test) until runners catch up. Be honest about this in CONTRIBUTING.md.

## Add CODEOWNERS, dependabot, editorconfig, swiftformat

- `.github/CODEOWNERS` — single owner is fine for now, but having the file means GitHub auto-requests review.
- `.github/dependabot.yml` — at minimum, watch `swift` package updates (Sparkle, mlx-swift) and `github-actions`.
- `.editorconfig` — 4-space indent for Swift, 2 for YAML/JSON, LF line endings, final newline. Standard.
- `.swiftformat` (Nick Lockwood) **or** `.swift-format` (Apple) — pick one and pin it. Without this, every contributor's PR has formatting churn.

## Single source of truth for version

Today: `VERSION` (file at root) = `0.4.0`. `project.yml` `MARKETING_VERSION: "0.4.0"`. Tags also exist in git.

Recommendation: drop `VERSION`. Source of truth = `project.yml` for build, `git tag v0.4.0` for releases. Update `CHANGELOG.md` to be the human-readable record. If a script needs to read the version, parse it from `project.yml`.

## Order of operations

Do these in batches and verify after each. Run from `CLAUDE.md`'s verification commands.

### Batch 1 — Risk-free hygiene (no build paths touched)
1. `rm -rf .deriveddata-* .build .gstack default.profraw`
2. `git rm --cached` the loose root icons and `.afdesign` source if any are tracked, then `rm` from disk; add `*.afdesign~lock~` to `.gitignore`.
3. **Don't** `git add "SVG External logo files/"`. Either delete from disk or move outside the repo.
4. Add `brand/mark-light.svg` and `brand/mark-dark.svg` so the README stops being broken.
5. Verify: `swift build` and `xcodebuild ... build` should still pass.

### Batch 2 — Doc surface
1. `mkdir -p docs/archive/design-iterations docs/mockups docs/screenshots`
2. `git mv` the files per the design/ → docs/ table above.
3. Update README links and any internal cross-links.
4. Delete the now-empty `design/` directory.
5. Move `codex/` to `docs/archive/runtime-migration-phases/` or delete.
6. Move `TODOS.md` to `docs/archive/2026-04-todos.md` or delete.
7. Resolve `ARCHITECTURE.md` vs `docs/architecture.md`: pick one as canonical, retitle the other ("System overview for newcomers" vs "Deep architecture reference") so the split is intentional.

### Batch 3 — Tooling and CI
1. Create `.github/workflows/ci.yml` and `xcodebuild.yml`.
2. Create `.editorconfig` and `.swiftformat`.
3. Create `.github/CODEOWNERS` and `.github/dependabot.yml`.
4. Push and watch the first CI run go green or fail. Fix what fails.

### Batch 4 — scripts/ rename and brand/ tidy
1. `git mv script scripts`
2. `git mv test-e2e.sh scripts/test-e2e.sh`
3. Restructure `brand/` per the section above.
4. Search the repo for any reference to `script/` (singular) and update.
5. Verify build.

### Batch 5 — Optional, deferable
1. Move `Resources/com.spatialduality.manifold.runtime.plist` to `Sources/ManifoldAgent/Resources/` and update `project.yml`. **This touches the post-build script** in `project.yml` — verify the LaunchAgent still bundles correctly.
2. Drop the root `VERSION` file once nothing references it.
3. Decide whether `.claude/agents`, `.claude/skills`, `.claude/rules` should ship in the public repo. They document the AI-tool collaboration model and align with the `CLAUDE.md` story; arguments either way.

## Risks and second-order effects to watch

- **`project.yml` references `${SRCROOT}/Resources/...` and `${SRCROOT}/.build/...`.** Moving `Resources/` or running CI in a way that doesn't share `.build` with Xcode will break the post-build script that bundles the LaunchAgent. Test with the full `xcodebuild` command, not just `swift build`.
- **README image references render on GitHub.** If you reorg `brand/` paths, every external link to the README image breaks. Pin the file paths first, then never move them again.
- **Contributors will fork the repo at v0.4.0.** Any path you change after launch creates pain for downstream PRs. Front-load the structural changes; don't dribble them out.
- **Deleting `design/` iteration drafts loses context.** If you regret it later, the only record is git history. Archiving (move to `docs/archive/`) is cheap insurance and preferred over rm.
- **Removing third-party logos that the app currently displays in UI** would be a UX regression. Verify the app uses SF Symbol + tinted dot, not the trademarked wordmark, before you decide the `SVG External logo files/` directory is unused.
- **CI runner availability** for macOS 26 / Xcode 26 may force you to either lower CI's min OS or self-host. Document the gap honestly in CONTRIBUTING.md rather than appearing to test on what you don't.

## What this is not

- Not a refactor of `Sources/` or `ManifoldApp/` — those map to the build and are working.
- Not a rewrite of any doc content. This is paths, names, and the index.
- Not a license or governance change. Apache-2.0 stays.
