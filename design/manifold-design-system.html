10. Accessibility Coverage

✓ @Environment(\.accessibilityReduceMotion) in SetupAssistantView
✓ .accessibilityHidden(true) on decorative icons
✓ .accessibilityElement(children: .combine) on compound rows
✓ .accessibilityAddTraits(.isSelected) on command palette

Gaps to address
✗ reduceMotion not checked in MainView animations
✗ reduceMotion not checked in AgentPolicyCard
✗ Missing .accessibilityHint() on AgentFocusControl
✗ Undo toasts time out even for VoiceOver users
✗ No ⌘Z keyboard fallback for undo actions
✗ Not all custom buttons have explicit labels
Decisions For Review
1. Body text: .callout vs .body
Currently mixed across views. .callout is 14pt, .body is 13pt on macOS. Pick one as the default and use the other for a specific purpose, or accept the 1pt difference as intentional hierarchy.
2. Opacity consolidation: 0.05 vs 0.06
Nearly indistinguishable. Should we collapse to a single "subtle" tier at 0.06 (or 0.05)?
3. The .easeOut(1.0) in SessionEventRow
Only remaining bezier curve animation. Convert to .spring(duration: 0.8) for consistency, or keep as a deliberate slow fade for "revert success"?
4. Activity drawer material
.regularMaterial on the activity drawer background. Should it use system inspector chrome instead now that it's positioned as a side panel? Or is the material intentional for the floating overlay feel?
5. Toolbar tint opacity
Currently 0.06 for active work block toolbar tint. The design guide suggested 0.08. Which feels right? Lower = more subtle, higher = more noticeable.
6. Empty state upgrade scope
OverviewView empty state is currently passive text. Should it get an actionable "Connect an AI Agent" button that opens setup? That's a behavior change, not just polish.
